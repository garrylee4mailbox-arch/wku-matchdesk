# WKU 羽毛球比赛记录系统 v1.0.0

## 日常使用

1. 将使用包完整解压，保持 `WKU-MatchDesk.exe` 与 `ui` 文件夹在一起。日常双击外层“开始记录比赛.cmd”，会打开本机浏览器并使用同目录的 data。
2. 在“队员名单”维护队员。可以从已知旧资料整理一份可编辑名单；性别留未知。临时队员可取消“临时”标记转固定。
3. 创建赛事 → 勾选参赛队员 → 设置规则 → 确认双打搭档 / 分组 → 检查场数 → 生成赛程。
4. 录分保存后停留在原比赛卡片，不会自动回到顶部。每场点“记分”，完整比分点“确认完赛”；未打完点“保存草稿”。上方显示“已保存到本机文件”后才算保存成功。
5. 在“晋级与赛程”查看真实战绩。遇同分可加赛，再人工确认顺序。晋级位置不改写战绩。
6. 最新轮次记分显示在最前面；下一阶段必须检查、确认，说明选填。确认后显示名单，可再次核对；进行后的场次不会因前轮纠错被自动删除。到“管理员”逐项处理影响。
7. 全部比赛结束后，点击自动出现的“查看比赛结果”提示，确认实际成绩后归档。决赛没打可保留1—2名未决，不能凭空宣布冠军。随时导出备份。

程序在右下角系统托盘保持运行。关闭网页不会退出程序；从托盘菜单可重新打开。结束时通过托盘菜单退出。无需安装 Node.js、Python 或数据库；使用 Windows 自带 .NET Framework 4.x 与现代 Edge/Chrome 浏览器。EXE 未作数字签名。

## 三种导出

- CSV：包含全部实际比赛、各阶段统计和全部名次，供分享或 Excel 阅读，不能恢复进度。
- 打印 / PDF：通过浏览器打印对话框“另存为 PDF”；结果栏按配置只显示前四，前面轮次仍完整输出。完整赛程图另以 SVG 导出，可用浏览器打开打印。
- 单届完整包：具体赛事右上方“赛事包”，包括名单快照、配置、比分、晋级、日志、修订与实际成绩；另一台电脑导入可继续操作。
- 全量备份：包括队员、全部赛事、模板、待改进、设置、已保留的旧版原始文件。换电脑请用它。

## 保存位置与恢复

本机部署通过上级目录的 `开始记录比赛.cmd` 启动，入口设置 `WKU_DATA_DIR` 为同目录的 `data`。正式数据位于 `D:\NEW_WKU\WKU羽毛球校队\队内比赛\data\state.json`，自动快照位于 `data\backups`。源码、交付包、代码修改存档均位于当前项目目录。

直接启动 EXE 且未设置 `WKU_DATA_DIR` 时，通用默认值仍为 `%LOCALAPPDATA%\WKU MatchDesk\data\state.json`。界面“保存与备份”显示实际路径。更新程序时保留 data 文件夹。

每次保存以临时文件落盘后原子替换，替换前版本存入 `backups`，保留最近100次。可在界面预览并恢复快照。全量恢复会替换全库；单届导入按稳定ID判断新增或替换，不自动合并，同ID不会复制一份。每次恢复前当前数据库再备份。

若文件损坏导致无法启动：退出程序，先复制整个 data 文件夹到安全位置；将一份 `backups/*.json` 复制为 `state.json` 后重开。不要删除或覆盖唯一的旧文件。不能在运行中直接修改数据库。

右上角“回到上一步”支持放弃本次打开期间最近20次已保存的操作，并回到操作前的页面。确认框会列出将放弃的操作，刚才那一步的内容不再作为当前记录保存；重新启动后用自动快照或导出的备份恢复。保存失败时停止后续写入，重新载入最新数据后再操作。两个页面保存同一版本时，仅第一个能成功，第二个提示冲突，避免覆盖。

## 默认规则

单打、男女共赛、小组后同名次赛、单局11分先到即胜、排序为胜场→累计得分。累计得分为该组正式完赛中各局本方得分总和，非净胜分。草稿、同分加赛和趣味赛排除在原组累计得分外。

高级排序支持 wins、points、gameDiff、pointDiff、headToHead，按填写顺序比较。相互交手使用同分子集完整对阵的胜场；数据不足跳过该规则，全部规则仍相同则等待人工处理，不使用姓名或ID决胜。

弃权、退赛的是否计胜、是否保留本场已录得分，由管理员显式选择；既往场次默认保留，需排除时逐场作废。轮空不造比分。

淘汰默认只加季军赛，其他淘汰者按实际淘汰轮次保留并列范围。自动建议与人工确认分开。补录支持缺失比分、未决和近似排名。人工裁定名次可能超出自动赛制，需要填写依据。

## 构建源码

源码目录为本 README 所在目录，`ui/core` 为规则与数据模型，`ui/actions` 为操作流程，`ui/views` 为界面，`ui/storage.js` 为存储接口，`native` 为本机文件服务，`tests` 为回归验证，`docs` 为迁移与交付记录。

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

输出 `build\WKU-MatchDesk`。没有第三方运行依赖，package-lock.json 锁定空依赖集合。开发测试需 Node.js：`npm test`，不需要 npm install。构建用 Windows 自带 C# 编译器。

## 手机与当前范围

响应式页面适配手机尺寸，但当前程序只监听 127.0.0.1，手机不能连接电脑录分。局域网配对和受限权限、公网查看、积分榜、轮换搭档双打、团体赛均未实现，已预置为待改进。

旧版使用固定九人、不同的排名算法；导入旧 JSON 只查看并保存原始文件，不擅自换算名次或判定过去比赛。可手动补录有依据的实际记录。原始旧文件保持不变。

人工分组调整会保留旧对阵，管理员需核查影响后按场作废、改未进行对阵或新增比赛。双打替补保留原始参赛快照，只更新尚未开始场次的出场名单，必须说明原因。当前未自动生成所有低位排位赛，可手工添加。

实施范围、数据格式及实际验证见 docs 文件夹。用户在“待改进”中勾选完成属于人工记录，不代表自动验证。


## 创建比赛的新流程

先确认基本信息、参赛范围和名单（双打同时确认搭档），再到独立赛制定制页面选择现有三种赛制及中文计分、排名设置，最后在预览页面核对分组、首阶段对阵和预计场数。前两步仅保留本次页面草稿；最后点击“确认并生成赛程”才写入正式赛事。返回上一步可修改，名单和设置不丢失；更改赛制或参赛者后会重新生成预览分组。

## 直观确认晋级和对阵

点击“查看晋级名单与下一轮对阵”，在列表中拖动选手或使用上下按钮调整。小组赛后的晋级线以上为晋级名单；右侧实时显示下一轮谁与谁比赛。淘汰赛后列表注明上一轮胜者或轮空来源，决赛和季军赛分开安排。调整仅改变用于晋级的顺序及新对阵，不修改原始胜场和比分；填写依据并最终确认后保存。

## 取消赛事与问题排序

赛事临时取消时，点击赛事右上方“取消整届赛事”，再确认移除。本届将从赛事台和档案移除，无须补完比分或归档；固定队员库和其他赛事不变。误操作可立即点“回到上一步”恢复，重新打开程序后可通过自动快照恢复。

“待改进”中的未解决问题按高、中、低优先级排列，待处理和进行中使用同一规则；已解决的问题统一排在最后。同优先级保持原有先后顺序。新增、修改优先级、完成和重新打开后，页面即时重新排序。
